# 战役原僚机接管：三轮递归逆向计划

2026-10-31；基线 mp@4717943。用户已指定：本轮不使用任何 Toolhub 连接；本地 Ghidra 12.2 + JDK 25.0.5。

## 目标与对象定义

当前交付目标是单一战役世界中的本地双人分屏：P1 为权威主机角色，P2 复用原剧情僚机的原生 Actor。
后续网络客户机映射到该 P2；本轮先接两路本地输入。战役任务规则/脚本身份继续由原世界拥有。
原僚机是任务角色，不自动等于 PlayerContext[1]，也不自动等于 group[1]/actor[0]。
P2 机型/配装与双机选择尽量复用原生 VS 的选择流程；不将 VS 世界规则整体替换战役。
Gameplay 的人类控制必须排除该机体的自主 AI 飞行、目标和开火写入。播片/关键事件转交原生脚本，
P2 输入清零且退出场景时失效；不能删除 Actor、剧情引用或敌我身份来实现 AI 抑制。

## 递归工作法

每轮先记录问题和根函数，再追踪具体指令、读写者、调用者和原生虚表，最后更新本计划及下一轮范围。
每个结论分为静态事实、语义假设、设计决定与待实机证据；不能把模型测试替代游戏实现。

## 实现前证据门槛

1. 同一剧情僚机的 Actor、Unit、定义/资源、脚本引用和玩家上下文之间可验证的对应关系。
2. 指定 Actor 的全部自主飞行/武器决策入口，区分 AI 决策、物理更新与脚本驱动。
3. 第二玩家上下文和摄像机/HUD 的原生构造/初始化顺序与资源寿命。
4. VS 两机选择的实际模式入口、参数、返回/确认、取消和机型资源回填。
5. 普通 Gameplay、暂停、回放、播片、关键事件与离开的可观测控制权切换。
6. 每个 Hook 的完整 x64 ABI、原始调用/返回、重入与清理顺序。

门槛不足的部分保持开放，继续取证；不得为交付凑出猜测的 native 调用。
