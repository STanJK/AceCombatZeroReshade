## 非玩家链的进一步分解

115C20→119A30 对 Actor 的 `+360` 对象执行两次 1153A0 结构转移，
在对象的 `+3D8..3F4` 和 Actor pose 之间搬运数据，依条件调用
121880、121EB0、1228B0、12AA30 等路径，再把结果写回 Actor、模型、命中/销毁和音效。
这证明“僚机有一个可置空 AI 指针”是过度简化：控制、运动、武器、效果混在多个层级。
各路径语义仍须结合具体输入/输出和动态写入顺序核验，不能仅按函数大小或名字把整个链禁用。

12F340 中多个循环直接从 actor1 开始，除辅助操纵外也包含目标解除和跨 Unit 查询。
115C20 的 actor0 人类路径在更后面仍有 actor0 条件。两处必须一起设计，
否则可能出现 P2 输入产生了 pose，随后又被非玩家路径或编队逻辑重写。

## VS 选择结果不是无副作用接口

18C6C0 对两个槽分别处理选择状态，向 active profile 的 +24C/+250、+254/+258、+25C/+260
写 DWORD，并修改其他全局 UI/配置状态。16F6C0 的世界构造随后只取低 byte。
16D1C0 在切换 active profile 时会拷贝选择字段并更新控制配置；1BD460 初始化选择 UI 的槽位。
这些是可核对的读写链，但不是已证明可脱离 ModeHolder 调用的选机 API。

当前实现只读完整 DWORD，并对颜色表索引独立限界，不把 0x104 截断成机型 4。
选择页确认/取消/返回战役载入的事务仍须闭合；没有把这些入口接入战役 UI。

## 关键事件是复合条件

0D1780 从 `W+A8318 -> +10` 取得 controller；`controller+2D8` 是含两个指针的事件表，
第一个指针指向带 byte count 的表头，第二个指针指向 stride=48 的记录。
`controller+3C9` 是 byte 索引；记录首指针再指向事件种类 byte；`+3CC` 也是 byte 子状态，
`+3A8` 是 flags。事件链无对象或索引越界时不能杜撰一个普通 Gameplay 事件。

0D1780 对 world phase、事件种类/子状态、输入/任务标志作交叉处理，包含调用 10E220
清理玩家操纵的路径。因此新增取证同时记录原始事件和世界标志，**没有定义 phase=1 就能接管**。
还缺少逐任务事件语义和实测轨迹，事件 gate 未放行。
