# R5 计划：双视图输出、HUD 一次生产与生命周期闭合

承接 R4：动作查询 ABI 和机炮/其他武器已区分；相机/目标 action 复用要求按消费者隔离。
本轮不改变玩家数、不创建第二 Actor、不重跑模拟，追渲染包到实际 viewport/target 的消费者。

根：1FC350、18F920、19D160、194840、19CBF0、20F8E0、20F680、20B9C0、20C280、18FA80、
201840、201A40、20E000、20E490、20EA20、20ABE0、20E550、16E4C0。
适应性补根由实际调用与分派表决定，不能因旧文档名称就认定函数行为。

输出：

1. Camera 编码的 viewport/scissor/target 数据如何被解释，原生两个列表组能否独立清屏/呈现。
2. HUD 包生成与 GPU 执行是否同步；透明 HUD 层/机头平面复投影需在哪一层隔离，而非把 SceneClean 当 RGBA。
3. 保持一次模拟的 pass 顺序、场景共享 scratch、Camera/HUD 缓冲所有权、设备重置/换关时失效规则。
4. 给每个候选接点标注 S/H/D/O；输出最小运行实验与明确放行门槛。
5. 整理全部五轮证据、地址/接口/未闭合项，回写主计划和新目标归档导航；不将静态研究写成可玩实现。
