# R2 结果：独立 Camera 可研究，不能重跑玩家相机求解器

实际导出 r2（12 函数）、r2b（3 函数）。本轮取得 Camera 初始化、矩阵更新、包生成及玩家相机生产者证据。

## Camera 字节字段（S；语义进一步区分 S/H）

| 偏移 | 具体读写 | 含义/限制 |
| --- | --- | --- |
| 00/04 | 004E80 初始化 640/480，1FBEC0 作为比例分母 | 原生逻辑尺寸，不能直接等同当前桌面像素 |
| 08 | 初始化 512，矩阵生成消费 | 焦距/投影尺度候选 H；不是以度标注的 FOV |
| 0C/10、2C | 初始化深度类浮点参数，进入投影与比例计算 | 近远平面/辅助深度范围 H，需保持原生约定 |
| 14/16、18/1A | s16 矩形位置/宽高；默认宽高 512/448 | 主矩形；1FC350 同时用于命令编码 |
| 24/26、28/2A | 第二组 s16 位置/宽高，默认同上 | 裁剪/光栅矩形候选，不能只改一组尺寸 |
| 30/40 | 两组姿态输入传入 202C00；它调用 202230 后加位置并求逆 | 位置与旋转输入；不把原生四分量无条件当网络 quaternion |
| 50 | 202C00 写 4×4 矩阵，含 03A2E0 逆矩阵调用 | 视图变换 S/H |
| 90、D0 | 202C90 与后续计算生成两套投影矩阵 | legacy 光栅/归一化裁剪用途待消费者细化 |
| 110、150 | 分别组合上述矩阵与 50 的矩阵，写 4×4 结果 | 两套组合变换；乘法行/列约定按实际 helper 核验，不凭名字调换顺序 |
| 190/194、198/19C | 比例与中心偏移；1FBEC0 根据矩形和 flags 重算 | 自定义布局必须与这些派生字段一致 |
| 1A0 | bit0/1 控制由整数矩形重算比例/中心 | 修改派生矩阵不能忽略更新规则 |
| 1A8/1A9/1AA | 多分区/偏移控制，0D2580 每视图写入 | 不是独立 P2 身份 |
| 1B0..1B5 | 1FC350 打包到 render-buffer 命令 | 不把它当 HWND、DXGI texture 或屏幕编号 |

004E80 仅以 RCX 接收目标，返回 RAX=原目标；无分配调用。
1FBEC0 以单 Camera 指针更新数据；202C90 有大量混合浮点/栈参数，未来适配优先通过 1FBEC0。
1FC350 消费 RCX=Camera、RDX=packet，写 C0 字节命令并返回 packet+C0。
这些是存储/副作用证据，不等于已通过运行时适配。

## 避开的耦合

- 106F30 会读动作、调用玩家/目标相关处理并修改 P 状态，不适合为第二视图重复调用。
- 107320 更新 P 的姿态/平滑状态，再经 111D40 求解两套相机。
- **111D40 还消费输入并调用 242630 随机数。** 第二视图若再跑整套玩家相机解算，会改变输入/抖动和随机消费。
- P+2094 CameraMode 会改变模型/座舱/HUD的生成分支，不能只把它当一个旋转矩阵开关。
- 1580C0 使用 C70..C84 一组观察角限制；继续保持“不能把 90/60/120 角限当 FOV”的修正。

## 对 R3/R5 的回写

D：从已有飞机姿态和独立的 P2 yaw/pitch 构造 Camera，仅调用已确认的数据型矩阵更新；
不重跑 1040C0、106F30、111D40，也不改变 P1 的 CameraMode 来模拟 P2 转头。
R3 追 108620→0AE510，区分其消费 P 内嵌相机和传入相机的路径；
R5 追 1FC350 的矩形/target 命令到 D3D12 层，确认逻辑尺寸与实际输出纹理的缩放关系。
