# R3 结果：HUD 有明确总入口和混合空间，重画并非纯读取

本轮实际导出 r3（9 函数）、r3b（15 函数）、r3c（6 函数）。
结论服务于用户新约束：一份 HUD 状态、机头固定基准、两个独立观察视角。

## HUD 总入口与共享状态（S）

0D2580→108620→0AE510 的直接调用链已经在本轮复核。
108620 的 `108959 LEA R8,[RSI+10B0]`、`108967 LEA RCX,[RSI+1868]`，
在 108976 调用 0AE510：HUD 子对象来自 `P+1868`，相机硬编码来自 `P+10B0`，
R9 是 `P+2040` 的 group manager，第五参数经栈传递（来源 P+1FC8，原值必须保留）。
因此“第二场景相机传进 108620，HUD 自然独立”不成立。

0AE510 读取同一 HUD 子对象的武器/标志/对象指针，进而消费同一飞机、目标、原生弹药/锁定资源。
共享语义状态无需新增 Actor 或 PlayerContext。其 actor 查询仍包含 group 的首 Actor 假设；
保持原 P0 和原飞机避开新增角色映射需求。

## 三类显示几何（S/H）

| 类别 | 本轮具体证据 | 对双视图的要求 |
| --- | --- | --- |
| 摄像机投影相关 HUD | 0AE510 按 camera+08、198/19C 写 H+390/394 一类派生值；0B3560 创建局部 Camera 并重算矩阵 | HUD不能仅复制数据后继续依赖 P1 当前转头相机；建立机头基准 Camera |
| 世界目标标记/包围信息 | 0B05E0、0B30F0 从目标 Actor+258 取世界位置，使用 camera+150 做 202ED0 裁剪，再用 +110 矩阵投影 | 目标 ID/状态共享，像素坐标不是可跨视角复用的状态 |
| 二维固定布局、文字/菜单类包 | 0AE510 写一组布局常数；0B1680、0BBE30 等发出二维图元/资源包 | 要满足机头固定，需把这些像素布局挂到机体参考平面/角空间，不能默认贴 P2 屏幕中心 |

202ED0 已确认是齐次变换后范围测试；0AE510 的 child draw 仍有大量间接虚表调用，
当前不把每个图元的用户名称或各武器类型全部强行标定。

## 不能重复推进的状态（S）

- HUD 生产者 0B7B40 归一化角度、更新状态轮换/计数，并在特定分支调用 242630 RNG。
  第二摄像机不能导致它再次执行。
- 0AE510 也会改 H 的 flags、投影缓存和布局；末尾还写 HUD 子对象指向资源的可见性字段。
  它不是无副作用的纯 draw；浅复制 H 本身不能隔离所有 pointee 写入。
- 108620 还依 P+2094 产生模型/座舱/表现命令；复制整个 P 或临时改全局 CameraMode 都不是已证明的隔离方案。

## 回写后的实现候选（D，不是已完成代码）

首选研究 **一次 HUD 数据推进、一个机头基准 HUD 生成、两份显示变换**。
P1/P2 scene camera 分别控制场景；HudReferenceCamera 依据机体姿态，不跟随自由转头。

1. 全 HUD 生成到独立 RGBA/图元层，再按机体固定平面/角空间显示，可最大限度复用原 HUD 内容。
2. 若两视图原点相同，旋转重投影可研究矩阵形式 `K_view * R_relative * inverse(K_hud)`；
   正确矩阵约定、透明混合和近裁剪须验证。换座位/平移后，单平面不能保证所有世界目标标记的视差正确。
3. 如需世界标记严格对应目标，则沿 0B05E0/0B30F0 的原生世界位置重投影，不能把 P1 屏幕坐标当权威数据。
4. 不能依靠 final−SceneClean 唯一恢复 HUD 的颜色与 alpha；现有 SceneClean 是场景捕获，不是透明 HUD 层。

R4 新增对 0B7B40、111D40、10F600 的采样/副作用审计，保证输入和 HUD 只推进一次。
R5 必须定位 HUD 开始/结束与 target/viewport 命令的实际 GPU 消费，评估独立 HUD 层的正确生成方式。
