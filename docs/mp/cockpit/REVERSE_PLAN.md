# 单机体双座、主机双视角：五轮递归逆向计划

日期：2026-11-03（Asia/Shanghai）；基线 mp@5b0090a。
本轮仅使用本地 Ghidra 12.2＋JDK 25.0.5，不连接任何 Toolhub。

## 当前目标与 HUD 契约

主机仅模拟一个战役世界、一架玩家飞机。P1 控制机动、机炮和自身视角；
P2 控制其余武器系统和独立视角。主机生成两个视图，P2 画面可合成到主窗口、
输出辅助窗口或交给虚拟显示器/串流端。当前优先取证，不在本轮宣称完成运行补丁。

两人共享同一份原生飞机和 HUD 语义状态：目标、锁定、弹药、武器、速度/高度、任务信息。
HUD 的方向基准保持在机头/机体坐标系；摄像机转向不能把准星、武器轴线和目标状态一起改掉。
P2 转头时，机头参考的 HUD 内容应按 P2 视角重新投影，可偏移、裁切或出视野，
不能简单复制 P1 最终屏幕像素并始终贴在 P2 屏幕中心。
原生 HUD 中哪些内容已经按世界/机体投影、哪些是二维固定布局，必须逐类区分；
若采用完整 HUD 纹理平面重投影，也必须核验目标标记的几何正确性。

## 证据与放行规则

- 原目标 SHA-256：43814d4b3292efd0a07fd71bef2f1670c0e5ac7cf2595c9e136d78451380a664。
- Ghidra C 是推断伪代码，指令、具体读写和调用位置是更强证据；不把 prototype 自动当成可调用 ABI。
- 每个结论标记 S（静态事实）、H（语义推断）、D（拟定设计）或 O（尚缺证据）。
- 构造双视图不得通过额外执行一次任务/世界 update 实现；一个权威 Tick 只模拟一次。
- 不假定增大视图数就有合法的第二套渲染缓冲；不假定 view owner=1 在单 PlayerContext 下有效。
- 当前不新建剧情僚机或第二人类 Actor，也不把本轮方向等同于双世界状态同步。
- 无完整游戏资产/Windows HIL 时，仅报告静态可行性及明确的运行验收，不编造实际画面。
