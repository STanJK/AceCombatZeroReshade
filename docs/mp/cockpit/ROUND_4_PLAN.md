# R4 计划：唯一玩家的分权输入与副作用边界

R3 证实 HUD/相机生产者消费输入、状态和 RNG；网络数据不得通过再次执行这些生产者来应用。
本轮追输入采样、动作查询、原生飞行/机炮/其他武器的调用前置条件，建立共享单机体的动作矩阵。

根：1040C0、187C80、187A40、187EC0、188A80、188180、188550、187390、201DC0、
111D40、10F600、0B7B40、1031B0、13ACE0、13D140、141200。

输出：

- query wrapper 的逻辑玩家索引、action ID、返回寄存器、held/edge/repeat 来源；
- 动作到飞行、机炮、其余武器、相机、菜单/僚机命令的可证明对应，未知项单列；
- P1/P2 摄像机输入不能通过改同一个 P+2094 实现；
- 主机唯一 native player update 的前后注入点，网络线程只入队，边沿和超时清零规则；
- 原生武器接受判定/资源/发射仍在主机执行，保留已有共享 HUD 生产，避免双重发射。

不把所有未分类动作默认分给 P2，不把 query 函数伪代码的 RCX/XMM artifact 当作真实多余参数。
结果回写 R5 的 tick/render 边界及最终最小接入条件。
