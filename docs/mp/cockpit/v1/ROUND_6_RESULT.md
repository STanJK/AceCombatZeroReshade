# R6 回写：帧、模拟步与场景租约

本轮用本地 Ghidra 导出 r6/r6b，并扫描四组操作数。以下地址为 RVA。计数和分支均来自固定 SHA 的指令。

| 观察点 | 静态结论 | V1 用法 |
| --- | --- | --- |
| 1FF900 → 201DC0 | 主循环先采样输入，再调 Holder +30/+38 | 记录 input_sample_id，等待活动消费者再冻结 |
| 2010D0 / 201100 | 都重新读取 Holder+48 当前索引和槽指针。前者调 mode+20，后者尾跳 mode+28 | 更新后重新验证当前 mode 和 W。更新触发换模式时，旧 ready 不可沿用 |
| 16E89E → 0D1780 → 0D1D6C → 0CE880 | GameControl ready 后进入任务驱动。驱动含阶段分支，只有指定路径进入 0CE880 | 允许窗口需要已观测的活动路径及同一 W |
| 0CF038 / 0CF865 | 两处都调用 1040C0。前者由 W+A8790 低两位进入，且 0CF020/28 先设置 P+2058 bit1 和 P+1C20 bit6。另一条在对应活动路径先清除这些位，使用 RCX=P、DL=槽、R8=W+6A130 | 暂停/菜单分支拒绝角色替换。活动调用点仍需核对原生武器控制位与任务阶段 |
| 0CFF20 | INC dword [W+A878C]。扫描的其余两处直接命中是 0CD8BC 和 16DC9C 初始化写入 | 作为本场景逻辑步候选，回绕/重置用场景租约处理。用 HIL 验证其与玩家、飞行、武器推进的对应 |
| 16E9B0 → 0D2580 | ready 门槛后建场景列表，未 ready 有不同列表路径 | 双视图产包只进入已接纳的同场景帧 |
| 1FFB7D → 1FE9C0 | 1FF1EF/1FF202 两次 parser 调用由 render+ D0 的 0x20 位门控；随后轮换 +DF、收尾，并于 1FF312 调 20C280。下一帧准备受 32C93C 控制 | 列表建包、翻转、parser 消费与 Present 分别计数。跳过 parser 时废弃该批发布资格 |
| 200FF0 / 201070 / 16E4C0 | replace/pop 先走当前 mode 的 leave。16E737 置 32C933 为 0，16E780 循环清理 arena 记录并退 mark | 进入 leave 前撤销场景租约，清理借用与输入。GPU 私有资源由 queue/fence 独立退役 |

0D1780/16E880 对 W+A8822 写入或消费 1、3、4、5、6、7、8 等状态。已证明 4/5/8、6 会走不同退场构造分支。扫描只报告直接位移/常量候选，经过基址变换和间接访问的写者仍需运行跟踪。21D4C0 比较 32C933/32C932，并在条件成立时清理两组设备槽字段，因此这组字节与输入设备行为有关。场景类型须由 mode、W、实际活动分支共同确认。

M0 使用三种序列。输入采样序列对应 1FF900，逻辑步序列在被接纳的活动作用域完成后提交，渲染帧序列在列表生产时分配。若后续缺失 parser 消费或场景/设备失效，则放弃该帧。每帧两视图共享帧键，暂停分支不会推进角色输入。R10 按 0CF865 的上下文追输入注入范围，R8 复核 parser 交接前的组和目标所有权。

HIL 先记录连续活动、按暂停、恢复、退出及重试的 mode 指针、W、A878C、两处 1040C0 调用点和 parser/present 计数。单独触发 resize 以验证 device_epoch。当前无游戏运行数据，G0/G6 仍需完成这些实验。
