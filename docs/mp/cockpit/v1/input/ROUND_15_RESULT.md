# R15 结果：取消与原生已经受理的操作

补导前后共 12 次导出。全程序扫描得到 35 个字面操作数候选，包含无关对象与立即数。以下结论来自反汇编中同一机体对象的控制流。

| 动作或路径 | 证据 | 取消的影响 |
| --- | --- | --- |
| 0E 目标短按 | `105A2B` 查询 held，`105A43–105A5E` 在未按且计数非零、低于门槛时置 `P+1EEE` bit 0 并清 `P+20A6` | 直接把曾按住的位写成零，会走正常松键分支。 |
| 26 目标操作 | `105A98` 查询 held，`105ACA–105B34` 在短按释放时处理目标标志，随后调用 `0C11C0` 和 `10B000`。`10B130` 读 `P+1EEE`。 | 清零可能切换目标相关状态，具体分支取决于当时标志和武器模式。 |
| 0C 发射请求 | `10338E` 查 pressed，`103425` 更新 `P+20C0`，`103430–103451` 设置或递减 `P+20BE`。未收到新 pressed 时，`103487–1034A8` 仍可能设置 `P+C3C`；`1034EF–103500` 可消费已有计数。同一函数的 `103A89` 调用 `13D140`。 | 丢弃 Bridge 队列会阻断新输入边沿。原生已受理的请求有独立生命周期，需观测从请求到武器生成及弹药变化的关系。 |
| 原生镜头 | `111FFC` 读 0E 的压力，`112036` 读同一动作 held。 | 回填 0E 可能影响原生镜头。开启前须验证两台私有相机及 HUD 的机头参考不受该分支影响。 |
| 原生重置 | `0C4ECF` 初始化覆盖 `P+20A8` 的字。 `102AB0` 的 `102F1C` 和 `10301E` 分别清 `P+20C0`、`P+20A8`，同一函数还重置多组武器和实体字段。 | 已找到生命周期写入，尚未找到可在 Bridge 失效时独立调用的轻量清理。设备层原型只写按钮字。 |

## 分段验收

- **首批 `0xA000`，动作 02/0C。** 同一固定任务分别测试短按、长按、快速按放和掉线前后。记录原始设备字、Bridge 受理序号、原生 pressed、挂起计数、发射事件和弹药。专测已经受理但尚未取得有效目标的情况，区分原生旧请求与 Bridge 新边沿。若需求要求掉线同时取消已受理发射，须先补足原生取消证据。
- **扩展 `0xB002`，再纳入 0E/26。** 对每键分别测试正常短按松开、长按松开和按住时失焦、断开、暂停或重试。正常松手按基线处理。失效时须证明不会触发意外目标操作；同时观测两路私有相机与机头 HUD。以实测结果决定能否启用这两个位。
- **交接。** 同一活动场景内角色设备失效后立即清除旧代，保持已移交位屏蔽。原生模式切换与功能关闭时，等接管位的中立边界及允许退出的生命周期条件成立后交回。重连须确认设备、槽位、绑定和中立采样。对无法再辨认来源的聚合记录，停止接纳 Bridge 输入，重新确认后再启用。

以上是对给定 PE 的静态结果。真实设备失效信号、活动作用域、发射在途行为和扩展位的取消验收仍需在原生游戏运行中确认。
