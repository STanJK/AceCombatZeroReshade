## 接入契约

1. 游戏线程使用 `188AB8 → 188ABD` 的返回边。以原始 PE 字节、活动战斗、非聚合采样、唯一且不同的角色设备及已读回的 profile 0 绑定为前置条件。角色绑定跟踪真实设备，记录号由本次轮询确定。先用只读跟踪证明两个选定物理源能同时到达，并确认主控逻辑槽及副记录的原生用途。
2. 每次采样先封存已发布的 Bridge 结果，再复制 P2 的接管位。队列载荷包含 `role_epoch`、`source_sample_id` 和按钮字。工作线程按来源顺序提交值，交接契约保留按下和松开的跃迁。输入 N 最早可在 N+1 回填，时间上界由实际采样与队列预算确定。
3. 游戏线程一次性替换 P1 记录的接管位，副记录只清相同的已分流位。默认映射下首批 `active_mask=0xA000`，扩展为 `0xB002`。P1 的轴和 `0x4000` 机炮位保持原值，P2 未授权位无法通过 Bridge 回填。原生流程形成快照、按键边沿及重复。
4. 设备、绑定、活动状态变化或队列超限时撤销旧代。无有效结果时，同一活动作用域内的接管位保持中立。暂停与菜单的交接须验证当前活动路径及原生 held 状态。按 [R15](ROUND_15_RESULT.md) 验收断开、重连、交接和在途发射，扩展位还需通过松键和相机测试。
