# R11 回写：统一设备层边界

本轮 r11/r11b 共导出 19 个入口。ACZ 输入的共通出口在 188AB8 调用 21D4C0 之后、188ABD 开始转换之前。RCX 指向 33ABE0，两条记录各 0x30 字节。该处适合只读复制并分流，也可作为本地设备快照过滤的候选。这里的两个索引表示游戏本次选定的输入记录。

| 来源或过程 | 地址级证据 |
| --- | --- |
| XInput | PE 的 XINPUT1_4.dll ordinal 2/3 由 21C530 用于状态读取和振动，后端条目 +90 存索引。21CD80 另加载 XInput1_4.dll，取 ordinal 0x6C 并遍历 0–3 做能力匹配 |
| DirectInput 路径 | 21CD80 通过 COM 实例枚举设备。21AAA0 调设备虚表 +C8/+48，读取 0x100 键盘和条件性的 0x10 鼠标记录，失败时尝试 +38。21B300 可读 KeyboardUI/KeyboardFlight，21AAA0 按 32C932 切换相关表 |
| 配置化设备 | 21A480 通过已选设备描述和映射生成输出，路径含 tm_api 属性调用。21A260 汇入共同记录格式 |
| Steam 绑定 | 2196C0 请求 SteamInput006。21CCA0 读取所选条目 +08 的 Steam handle，虚表 +138 返回候选 0–3 后按后端 +90 重定位枚举序号 |
| 记录有效性 | 21D740–21D773 初始化两条记录的有效性、位和轴，再执行 poll。+04 影响 188180 是否构建该槽；+28 为按钮位，+0C 起为轴/压力 float，+2C 为设备类型标记。21D4C0 对采样失败、特殊阶段另有分支 |
| 原生聚合 | 32C930 分支按 0x50 stride 扫多个绑定并 OR 按钮进第一条记录（21D4C0 的该分支尾部），之后清 32C930/31；失焦/特殊控制分支在 21D775 起另行处理 |

V1 首个原型采用两个可区分、经现场确认的设备实例。Bridge 记录设备身份、选定源记录、连接代次及样本序号。只有在普通采样路径且双方绑定可证明时启用角色过滤。枚举序号、XInput 槽、后端记录和 gameplay 逻辑槽分别记录。发生重绑或设备聚合时使旧角色样本失效。

保持定版分工，P1 保留机炮；屏蔽范围是交给 P2 的武器与目标控制。R12 追压力量化和按键位展开，找统一可掩码的物理通道及其实际绑定。继续保留原生轮询和震动处理。
