# R12 回写：绑定逆映射和物理通道碰撞

r12/r12b 共 15 次导出。187560 初始化两逻辑槽、每槽四 profile 的 0x2A 字节绑定。查询使用 b=(slot×4+D[2E])×0x2A，物理索引字节取映射对象 +10+b+action，+160 同一索引给长度，非单项再看下一字节决定组合规则。对 187560 的立即数写入按小端顺序复算并保留 JSON；运行值仍须读回核对。188180 的两个常规来源分支都把 D+2E 设为 0，+36 是另一类型标记。

| P0 profile 0 动作 | D 压力槽 | 用途 |
| --- | --- | --- |
| 02 | 0E | 武器模式 |
| 0C | 0D | 发射 |
| 0D | 10 | P1 机炮，保留 |
| 0E | 0F | 目标操作与原生相机共用 |
| 0F | FF | 未绑定 |
| 26 | 08 | 目标/锁定相关动作 |

188550 先写 D[00..17]，再扫描 D[00..23]，压力达到 0x20 时生成 +24/+28 两个 held 源字。187390 从 held 源生成 +38/+3C、+40/+44、+48/+4C。D[18..23] 不在该函数的常规赋值范围内，仍参与掩码形成。只改压力或只改 held 的后置方案会让 analog/held/pressed 看到不同数据。

逐 profile 比较候选武器/目标物理集合与其余动作。profile 0 的 08/0D/0E/0F 对 gameplay 绑定无跨动作碰撞。profile 1 的 26 使用 00+23，与 00 暂停共用物理通道。profile 2 的 0C 和组合 0B 共用 0D。profile 3 的 02/22 使用同一组合。首个原型冻结已确认的 profile 0 和独立绑定；其他 profile 不自动套掩码。0E 共用的是同一个动作的两个消费者，物理通道无碰撞的结论不覆盖这一点。

187480 的界面映射另有一套，201DC0 将选定设备同时发布到 32C8C0、32C8F0 和 32C8D8。角色过滤只在确认的活动战斗采样启用。R13 把 D 槽逐级映回 R11 的后端记录，验证能否只动一次原生按钮字。
