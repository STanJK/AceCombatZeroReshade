# R8 回写：列表共享游标、容量与延迟引用

本轮导出 r8/r8b/r8c。V1 的双视图可以沿用原生组编排作为探针，组数、字节容量、引用及目标状态各有独立条件。

## 视图状态与目标

0D2580 首先取 `W+67130 + A8829*5000`、`W+67138 + A8829*D10`、`W+67178 + A8829*28`。这些索引不随 view loop 递增。0D2A96 调 080940 重新写入 D10 scratch 的插值环境数据。随后 0D2580 把视图 Camera 指针存入 5000 scratch+280，复制姿态、比例和矩阵，并在 0D2AF9 覆写 Camera+2C 后重算。081880 读该 scratch 的内容并组织环境包。077C50 还把同一场景槽的子描述符绑定到两个对象，再经 202180 继续串接。由此可以区分已经拷贝入包的数据、指向 arena 的链接及仍借用外部的对象。完整保留清单需用 parser 轨迹确认。

单玩家条件下 0D292D–0D296D 把 W+228/230/234 写进两套 Camera 的 +1A8/1A9/1AA。V1 要比对 loop 内最后一次写入/矩阵更新，不能在 loop 外设置一次就假定有效。两 view 分支还触发 20EA20 及目标栈操作。20E490 依全局目标栈选择回绑分支，20A000 配置绑定/viewport，20EEB0 配置 scissor。任何额外 render pass 均须有完整配对的状态快照和目标租约。

0D265A 调 0C5BC0 读取任务子状态对象。返回 2 时进入专门建包并早退，虽然入口已经注册列表。M0 必须在更早的边界决定是否激活 V1。状态突变时恢复流程按已验证的事务边界处理。

## 接入决定

1. 首个 M3 实验固定任务和受控画质。只读采集根组、两组注册的预计固定开销、各 view 动态用量、指针表及切换目标状态。没有已证明的字节预留/容量机制时，仅记录，不开启第二视图写入。
2. 在单个原生建包序列内分别记录两个 view 的 begin/end，按原生组顺序提交。预先验证 group+0C、arena+21、当前游标、目标及数据租约。逐 view 的矩阵和包必须属于同一 FrameKey。
3. 对两个 view 的 scratch 写入和延迟读建立引用清单。已拷贝入包的字段可复用 scratch；在 parser 尚可访问的可变区域使用两份独立存储或同帧显式副本。只读资产随场景租约持有。原生 command arena 的 CPU 读取完成与新增 GPU surface 退役分别跟踪。
4. 验收两个 view 包区间、引用边、最终 scissor/RT/DS，逐帧比较 P1 基线并核对缺包/溢出。当前 G0/G1/G7 需要 HIL。

R9 直接使用本轮识别的引用表和 parser 栈边界，追 HUD 区间里的子引用及 pending batch，确定标签该随哪份数据传播。
