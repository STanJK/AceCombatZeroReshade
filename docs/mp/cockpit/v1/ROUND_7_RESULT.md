# R7 回写：相机矩阵、裁剪和同眼点 HUD

本地定点导出 r7/r7b/r7c。矩阵约定以下均按内存连续四个 float 为一行定义，点写成行向量。以当前 PE 指令与常量为依据。

## 存储和算术

- 005940 的 RCX=dst、RDX=A、R8=B。00594A–005958 取 A 第 0 列，005AA4–005AB3 与 B 第 0 行做点积，005AD5/005AFA 分别写 dst[0,0] 和 dst[1,0]。因此写入 B·A。原生允许 dst 与 A 同址。
- 202230 从 Camera+40/+44/+48 取三个 float。26F3F3 按 `[a,a+π/2,b,b+π/2]` 送到 26F390，26F3B0 走小角公式或 `[c,|c|+π/2]`。两个尾跳目标使用 1/π 和拆分 π 的系数（380C480/380C1C0/200/240）。轴旋转采用弧度。由三个局部 4×4 和 2023C5/2023F2/20241E 乘法可得，行向量下旋转顺序为 Rz(c)·Rx(a)·Ry(b)。定义 Rx 的 yz 块为 `[[cos,sin],[-sin,cos]]`，Ry 的 xz 块为 `[[cos,-sin],[sin,cos]]`，Rz 的 xy 块同 Rx。用户观察输入的正负方向要按游戏校准。
- 202C00 将眼点 xyz 加到旋转矩阵第 3 行的前三项，再走 03A2E0 逆矩阵。C50 为 view。1FC2A5 和 1FC2ED 的第三参指向 C50，分别写 C110=V·P90 和 C150=V·PD0。1074CB/1074F4 读 P+1D10/+1D20 进 P+10B0 的 pose，再调用矩阵更新。该位置是相机求解结果样本；机头基准仍须从独立机体姿态校准。
- 202C90 在 C90 中间矩阵 +38 写 qword 0x3f800000，即 m32=1、m33=0；与 +2C 的 m23=1 交换两行。第二次乘法翻转 Y/Z 行。最终 P90 行为 `[fx,0,0,0]; [0,-fy,0,0]; [-cx,-cy,-A,-1]; [0,0,B,0]`，fx/fy 含焦距、比例、分区。A=(far·dnear−near·dfar)/(far−near)，B=(dfar−dnear)·near·far/(far−near)。默认 eye-depth 近端映射 16777215，远端映射 1。该深度属于 legacy 路径。
- C150 使用 PD0 的归一化系数。单分区且默认 flags、比例时，sx=512/(640·0.5040000081)，sy=512/(480·0.5040000081)。行 2 为 `[0,0,-(far+near)/(far-near),-1]`，行 3 第三项为 `-2·near·far/(far-near)`。正前方为相机坐标 −Z，w=−z。202ED0 返回 0 表示 x/y/z 都严格在 (−w,+w) 内。模型另外拒绝非有限量。
- 0B0641/0B0659 用 C150 做目标点裁剪，0B08D4 取 C110 走 legacy 坐标路径。0B30F0 同样读目标及视图矩阵。两个投影在实际采集时各保留，避免直接用归一化深度替换原生包。

## 重投影合同

给归一化层的同眼点参考投影写 3×3 K，使 `[x,y,z]·K=[sx·x−ox·z,−sy·y−oy·z,−z]`。从参考层 `[u,v,1]` 恢复射线，做 `K_H^-1 · R_H · R_V^-1 · K_V` 后齐次除法。合成采样可用反方向映射。眼点平移相消的前提为两台 view 与 HUD reference 原点一致。最终 UV 和 PixelRect 单独定义，正 w、源覆盖范围及输出边界均需检查。

数值样例见 [camera-fixtures.json](../../../reverse-engineering/coop/cockpit/v1/camera-fixtures.json)。在二进制默认参数下，正前方 (0,0,−10) 的 NDC 为 (0,0)；眼点平移后相对向量相同则结果不变；相机 Y 分量 +π/6 后正前方点 x≈+0.916429；+2π/3、视线后方和近裁面边界拒绝。脚本从原 PE 读常量，以 binary64 计算这些关系并交叉比较直接投影与射线重映射。原生 FMA、运行时参数和游戏 pose 需实测比对。

M2 可按上述存储顺序建立私有相机数值基线，M4 以同一帧的 K/眼点/R/coverage 交付参考层。R8 追 0D2580 对 Camera 分区与列表注册的写入，决定怎样保持这份相机基线。
